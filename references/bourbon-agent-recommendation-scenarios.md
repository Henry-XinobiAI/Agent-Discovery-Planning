# bourbon-agent 추천 시나리오 (2026-11-13 받음)

bourbon-agent 쪽이 추천 대화를 어떤 방향으로 만들고 있는지 보여 준 시나리오 문서다. 공유 artifact(`https://claude.ai/artifact/R9SqbtzcVz4msxP9cxXCqw`, "추천 시나리오 대화")로 받았다. 아래 "원문"은 요약하지 않고 그대로 옮겼다. 원문 범례의 세 가지는 화자 이름표로 구분된다: `owner`는 owner가 한 말, 이름표가 `Ami`뿐인 것은 미리 적어 둔 Ami의 말, `Ami · 모델 답변 · …`은 모델이 실제로 쓴 답변이다(`찾아본 뒤 답변`은 추천을 부른 뒤, `찾아보지 않고 답변`은 부르지 않고 쓴 답).

## discovery 쪽에서 본 것 (2026-11-13)

bourbon-agent의 답을 어떻게 할지는 그쪽이 정한다(요청서 §4-1의 기준). 여기에는 우리 응답이 무엇을 뜻하는지, 이 흐름과 어떻게 맞물리는지만 적는다.

- **방향.** 넓은 주제는 되물어 구체적으로 만든 뒤 부르고, 먼저 제안할 때는 받아들인 뒤에만 부른다. 우리 쪽과 잘 맞는다. 넓은 tag(`travel`, `health` 등)만 겹친 사람은 근거 없는 사람으로 보고 하한(`agents.meaning_floor` 0.60)으로 거르므로(설계 §6-2), 주제가 구체적일수록 결과가 좋고, 주제에 이름이 들어가면 `names_not_found`도 의미가 생긴다.
- **이름은 `topic`에서만 읽는다.** 표기 호출은 `topic` 문장만 보고 `context`는 보지 않는다(`context`는 tag를 고를 때만 참고한다, 설계 §4). "오사카 3박 4일" 대화 뒤 "오코노미야키 잘 아는 사람"으로 부르면 오사카는 `names_not_found`의 대상이 아니다. 시나리오의 "오사카 오코노미야키"처럼 `topic`에 이름을 채워 보내는 것과 맞는다.
- **빈 결과의 뜻.** `empty_reason: no_matching_notes`는 "충분히 가까운 사람이 없었다"이지 "그 주제를 쓴 사람이 그 사람뿐이다"나 "아무도 쓰지 않았다"가 아니다. 넓은 주제가 그대로 남으면("그냥 아무나") dev에서 빈 결과가 나올 수 있다. 시나리오 "다른 사람을 요청"의 "다른 분은 찾지 못했어요"는 이 뜻과 맞고, "관련 노트를 남긴 분이 박서준 님밖에 안 보이네요"는 우리 응답이 말해 주는 범위를 넘는다.
- **같은 주제로 다시 물을 때.** 최근 7일 안에 같은 요청자에게 보여 준 사람은 점수가 낮아진다(`agents.shown_penalty`, 설계 §6-3). dev는 사람이 적어 꺼 두었으므로 다시 물으면 같은 사람이 나온다(시나리오 "같은 주제로 다시 요청"과 같다). 켜 둔 환경에서는 다른 사람이 먼저 나올 수 있다.
- **`names_not_found`가 나오는 장면이 없다.** 처음 피드백(샌프란 note가 없는데 여행 tag로 추천됨)이 그 장면이다. 이 필드를 쓰게 되면 볼 만한 경우: 이름이 안 보이는 경우("샌프란 여행" → `["샌프란"]`), 둘 중 하나만 안 보이는 경우("라프로익이랑 탈리스커" → `["탈리스커"]`), `null`(`degraded`에 `name_spellings_unavailable`), 빈 결과(`no_matching_notes`).
- **테스트 데이터.** 시나리오의 추천은 모두 같은 사람이고 note 제목이 주제를 그대로 따라간다. discovery를 흉내 낸 응답으로 보인다. 실제 dev 응답은 제목이 주제와 다르고 `reason.text`는 note 내용에서 쓴다. names_not_found가 dev에 배포된 뒤 dev discovery로 한 번 돌려 보면 차이가 보인다.
- **민감한 주제.** "허리 디스크 수술"처럼 건강 고민에서 먼저 제안하는 장면이 있다. discovery는 public note만 보고 순위를 정하며, 건강 주제를 따로 다루거나 막지 않는다. 제안할지는 bourbon-agent가 정한다.
- **discovery가 바꿀 것.** 이 시나리오로는 없다. 계약도 그대로다. 그쪽 클라이언트는 `names_not_found`를 무시하므로, 지금 배포해도 이 흐름에 영향이 없다.
